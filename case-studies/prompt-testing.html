01 / How I approach prompt testing

From vague idea to testable instruction

Prompt testing is about more than asking a model a question. It is about building a range of cases that expose weaknesses. I typically look for ambiguity, hidden assumptions, weak constraint handling, instruction conflicts and cases where a prompt sounds clear to a human but invites unstable model behaviour.

02 / What the work tends to involve

Typical activities

Across my evaluation roles, prompt testing has included comparing multiple outputs, assessing which one better followed the brief, documenting where the prompt itself introduced confusion and turning failure patterns into clearer guidance. It has also involved checking whether the expected output format was realistic for the prompt being used.

  • Designing edge cases and stress tests
  • Comparing outputs against the same prompt
  • Checking clarity, scope and instruction hierarchy
  • Translating recurrent failures into better evaluation notes
03 / Why I include it here

A core part of my positioning

Prompt testing is central to how I want to be understood professionally. It demonstrates proactive quality work, not just reactive scoring. It shows that I can help shape the conditions under which better outputs are produced.
